# Checking the successful-history comparison across the other archives

This is an exploratory robustness check of one published-run dataset. The earlier analysis found that a lookup-based checker identified 158/158 wrong destinations inserted into previously inspected GPT-4.1 workflows and 4/158 of the same errors in their original histories. A feasibility pass already found potential non-GPT-4.1 matches for 160/163 errors and inspected the availability of prior lookups. The new test actually replays and scores those matches. It is not a blind test on new tasks.

1. Include every previously verified wrong send or forward. For each error, use every other model archive with the same task, outbound tool and (for a forward) identical source message. A comparison episode must have at least one completed outbound call and every one of its committed destinations must be permitted. Exclude GPT-4.1 from the primary comparison. Select without inspecting lookup evidence, checker output, or the eventual counterfactual result. Within each eligible model episode use its first qualifying call, as in the earlier manuscript comparison. Also check every other qualifying position.
2. Preserve the exact recorded wrong destination, all other action arguments, surrogate IDs and the assistant's original text. Replay the in-memory WorkBench operations, check archived receipts on the original trajectory, and verify the native committed outbox destination on the changed call. Capture the canonical-alias LangSmith export using the project's prior configuration. Apply the same bounded checker at the target step using only prior lookups. Also capture raw and check the unchanged original history. Retain failed validations with the affected denominators. Reproduce the old GPT-4.1 comparison separately.
3. Report counts for the original 158 error actions and, separately, all newly matchable errors. Each original agent error gets one vote. For that error average the detection indicators over eligible comparison models. Also report raw counts of placements, the number of errors detected with every/any comparison model, and the result for the genuine actions on the identical error set. Models can share tasks and different errors can reuse exactly the same placement.
4. As sensitivity checks, restrict comparison histories to those judged correct by WorkBench's full final-state evaluator, inspect every eligible call position, and give each task equal weight. Check that the counterfactual never gets approved for a genuinely prohibited destination, count any exceptions, and compare the native results to the raw recorded directory evidence. A drop from 100% is allowed. Whether the wide gap survives the change in comparison histories is the question.

Use the existing pinned archives, local Python, WorkBench's in-memory mailbox and native SDK capture without network connections. No new language-model inference, email delivery, or manuscript changes.
