# Can a genuine wrong send and a corrected send produce the same export?

Exploratory follow-up, after scoring the natural actions and their matches to the GPT-4.1 donor. The number of whole-export equalities in this comparison has not yet been measured.

For each of the 163 verified wrong outbound operations, retain the original archived history, every other action and observation, all assistant text, and the final answer. Change only this occurrence of the recipient to a permitted address. Run the call locally before and after the correction and verify opposite recipient labels and identical native receipts. The pair is about the named operation; other errors in the same episode remain possible. The 50 task requests and pinned company directory independently determine the allowed set. Compare every permitted recipient, so a task naming two employees cannot gain a collision by cherry-picking one.

Capture the full native LangSmith export using the same layout as the paper, with fixed IDs/times, once with raw addresses, once with shared masking, and once with literal and with backend-canonicalized first-occurrence aliases. Count per-action equality for all and for any permitted correction. Report counts separately for instructions naming one person, episodes with one completed outbound action, and the full group. Validate stored digests for every original unmodified capture. Mark the corrected half as counterfactual. These equalities are structural comparisons under the specified exporter and its per-run numbering. They are not observed pairs of runs or a success rate for attacks, and equality of opaque token values under other alias policies is a different test.

As a positive control, retain a single execution-time bit indicating membership of the committed destination in the benchmark directory. Check whether it distinguishes these pairs. Give that method credit when it works and test its limits on the previously recorded wrong-coworker controls.
