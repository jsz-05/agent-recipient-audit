# Matched check on the original recipient question

This follow-up was specified after the initial archive analysis found four conclusive violations among 163 completed actions addressed outside the permitted set. It is exploratory.

For each of those actions, use the original, previously examined GPT-4.1 episode with the same user task. Select the first successful action in that episode with the same tool and, for forwards, the same source email ID. Substitute only the particular destination the other agent used. Replay that call and the preceding donor history with WorkBench’s own in-memory tools, verify the new outbox row and receipt, and run the same per-action canonical-alias checker on the captured export. Keep a separate count for actions without a matched tool and source. Compare all eligible donor positions as a sensitivity check; never count those placements as independent observations.

For the unmodified archive, independently replay every completed send and forward from its actual arguments against the benchmark mailbox and compare the native receipt and committed destination. Count successful intended-recipient directory lookups preceding each natural wrong action and each insufficient judgment. Check whether any directory reply includes any intended address even under a nonstandard query. Separate the literal domain, directory membership, and canonical-alias checks. A negative directory-membership result rules out a permitted recipient only because all these tasks name employees in the closed directory. Test membership alone against the existing within-directory controls.

Report the count of distinct episodes, tasks, and model archives. Repeated messages and multiple models on the same tasks are not independent draws from deployments.
